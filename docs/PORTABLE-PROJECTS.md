# BootCaT portable project format, version 1

A `.bootcat` file is an ordinary ZIP with UTF-8 entry names, STORE (method 0, no compression), and CRC-32 checksums. ZIP64 is supported for large sizes, offsets and entry counts. Encryption, multipart archives, data descriptors, duplicate entries, path traversal and compressed entries are rejected. This is a project format, not a general ZIP importer; changing the extension of an existing corpus export does not make it importable.

`project.json` contains `format: "BootCaTProject"`, `version: 1`, `appVersion`, `savedAt` (ISO timestamp), and `snapshot`. Unknown format versions are rejected with an explicit compatibility message. The manifest has a 64 MiB UTF-8 limit to bound JSON parsing. Original/text payloads are separate ZIP entries, so this is not a total project size limit. Browser storage and native Blob capacity remain the practical limits.

The snapshot contains `project` (name, language and source identity) and `stores`: arrays named `meta`, `documents`, `files`, `texts` and `pages`. These preserve all retained records, including failed attempts, unselected originals, edit revisions, baseline/raw text and queued captures. A native Blob is represented in JSON as `{ "$blob": "entry/path", "size": N, "type": "MIME type" }`. Pending HTML strings use the same representation with `text: true` and decode back to UTF-8 text. Each reference has one payload entry. Original file keys are exposed under `originals/`; other payloads live under `data/`. MIME types are metadata, not permission to render or execute a file.

A reader validates every checksum and reference and rejects extra/missing entries, unsafe URLs/paths, invalid record identities and malformed required metadata. ZIP data is processed as Blob slices and streamed for checksums; it is never extracted onto the host filesystem or rendered as active HTML. Portable data cannot install extension code or alter user preferences.

On import the project receives a new local UUID. The `active` metadata marker is replaced, running batch state becomes stopped, and the old corpus-export receipt is discarded. Document/collection identifiers remain stable so drafts, edits and provenance still refer to the same records. Search tab/session state is omitted; completed queries are reconstructed from collection provenance. No live browser tabs or network jobs are resumed. Pending captured originals are handed to the normal workspace extraction queue after opening.

Import first validates into a separate short-lived local transfer database. An atomic read/write transaction checks the expected current project identity, clears and restores all five project stores, and writes the authoritative active marker with recovery metadata. A failed transaction restores the old records. The background then resets tab tracking and publishes the imported identity/collections to extension-local storage, retaining settings, collection-control choices and user defaults. If interrupted after the database commit, the active marker recovers the imported project and collections on the next read. Transfer records are deleted when consumed; abandoned records expire after one hour and are removed on subsequent staging.

Saving uses a single read-only transaction for all project stores, combined with background-serialized project identity and current collection metadata. The UI flushes draft writes and obtains an exclusive project-work lock first. Originals and text Blob references are snapshotted together, including inbox-to-corpus handoffs, so a concurrent committed edit appears entirely before or after the snapshot. Save Project is a download, not a persistent file handle: every save can create a separate copy. The user must verify the downloaded file before discarding local project data.

Before starting the project download, Save Project consumes the completed archive stream into an independent native Blob. The browser download therefore does not retain IndexedDB-backed file streams from the temporary snapshot. This adds a native archive copy (subject to browser storage/memory capacity), but avoids a project-sized JavaScript ArrayBuffer and reports stream-read failures before starting a partial download. Browser tests verify actual completed Save Project downloads, not just in-page archive reads, in both Chromium and Firefox with persisted document originals.
